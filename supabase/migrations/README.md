# Миграции базы данных

Исторические SQL-миграции для Supabase. Каждое изменение БД — **отдельный
файл**, применяемый по порядку. Никогда не правим уже применённые файлы —
для нового изменения создаём новый файл.

## Как назвать файл

```
<YYYYMMDDHHMMSS>_<описание>.sql
```

- дата/время в начале имени — чтобы по имени файла было понятно, **когда**
  изменение создано/применено, и файлы сортировались по порядку;
- пример: `20261128155108_save_recipe_rpc.sql`.

В шапке каждого файла пишем дату создания/применения и назначение.

## Как накатывать

1. В SQL-редакторе Supabase применяем файлы **в алфавитном порядке имён**
   (= хронологический порядок).
2. На свежем проекте применяем **все** файлы по порядку — получится полная
   текущая схема.
3. На уже развёрнутой БД применяем только новые файлы (те, что ещё не
   залиты).

## Правила (чтобы не было расхождений)

- **Одно изменение = один файл.** Не дописываем новое в `0001_init.sql` или
  в уже применённый файл.
- **Не редактируем применённые миграции.** Если нужно что-то поменять —
  создаём новую миграцию.
- **Не удаляем старые файлы** — это история применения.
- Файлы пишутся идемпотентно, где возможно (`create or replace`,
  `drop ... if exists`), чтобы повторное применение не ломало схему.
